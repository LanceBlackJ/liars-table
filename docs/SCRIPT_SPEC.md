# 本子格式说明

一个本子就是 `data/scripts/` 下的一个 JSON 文件。游戏会把它**机械地**切成每个角色各自能看到的那一份，
AI 只拿得到自己那份——所以写本子时最重要的一条纪律是：**真相只写在数据里，从不写进“给谁看”的文字里**。

> 最快的上手方式不是读这篇文档，而是：
> 1. `python scripts/make_template.py` 生成模板
> 2. 复制 `data/scripts/community/_template.json`，改名、改内容
> 3. 每改一轮跑 `python scripts/check_script.py 你的文件.json`
>
> 模板是一个**真能玩**的迷你本子，每个机制都用了一次。从“能通过自检”的状态开始改，比从空白文件摸格式容易得多。

---

## 1. 整体结构

```
Script
├─ script_id          文件名必须与它一致（加载器靠文件名找本子）
├─ meta               标题、幕数、搜证次数、标签、作者
├─ setting            公开背景、地图、时段
├─ case               死者、案发时段/地点、凶器、死因、谁发现的
├─ characters[]       角色（嫌疑人 + 可选的证人 NPC）
├─ timeline[]         案发当晚每个人每个时段在哪、干了什么、被谁看见
├─ clues[]            线索（搜来的 + 拼出来的）
├─ interludes[]       幕间突发事件
└─ solution           凶手、推理链、关键线索、答卷
```

---

## 2. meta

| 字段 | 说明 |
|---|---|
| `title` / `tagline` | 书名与一句话简介，出现在选本页 |
| `player_count` | **角色总数**（含证人）。必须等于 `characters` 的个数 |
| `difficulty` | `easy` / `medium` / `hard` |
| `estimated_minutes` | 预计时长（分钟），选本页展示 |
| `acts` | `2` 或 `3`。**默认 2**（第一幕 → 幕间 → 第二幕 → 终局）；写 `3` 多出第三幕 |
| `search_budget` | 每幕每人几次搜证，长度必须等于 `acts`，例 `[3, 2, 2]`。不写用引擎默认 |
| `tags` | 如 `["断片","硬核"]`，仅展示用 |
| `author` | 署名 |

## 3. 角色 `characters[]`

```jsonc
{
  "id": "t1",                    // 全本唯一
  "name": "梁账房",
  "public_role": "茶室账房先生",   // 所有人都看得见的身份
  "private_secret": "…",         // 只有他自己知道的秘密
  "motive": "…",                 // 为什么这个秘密不能曝光
  "is_murderer": true,           // 全本恰好一个
  "is_npc": false,               // true = 证人，见下
  "personality": "…",            // 喂给 AI，不展示给别人
  "speech_style": "…",           // 说话方式，同时用来挑朗读音色
  "voice": "m",                  // "f" / "m"，朗读用，不写按发型猜
  "avatar": { "hair": "short", "hair_color": "black", "skin": "mid",
              "garment": "slate", "accessory": "none" },
  "personal_goals": [ { "id": "t1g1", "type": "conceal", "text": "…" } ],
  "cover_story": { … },          // 只有凶手有，且必须有
  "acts": [ { … } ],             // 第 2、3 幕追加的剧本，见 §6
  "amnesia_slots": ["20:00"]     // 断片的时段，见 §7
}
```

**个人目标 `type`**：`conceal` 隐瞒 / `acquire` 取得 / `protect` 保护 / `expose` 揭穿。
每个非凶手、非证人的嫌疑人**至少要有一个 `conceal`**——没有隐瞒动机的人，十分钟就结案了。

**判定规则（要理解它才能写好目标）**：个人目标没达成，就算票对了凶手也不算完全胜利。
目标由 AI 裁判按“公开记录”判定：
- `conceal`：秘密在公开场合被说破才算失败（自己说漏或被别人当众坐实）。被怀疑、被问到但没承认**不算**失败。
- `acquire`：记录里要有他实际拿到那样东西的动作。
- `protect`：被保护的对象在结束时没有受损。
- `expose`：要在公开场合说出来并且被其他人接受。

> ⚠️ 目标文字要写完整的句子。`不要让人对那沓发票`（缺“起疑”）这种半截话，玩家和 AI 都会读成病句。
> `check_script` 会帮你抓这种。

### 证人（NPC）`is_npc: true`

管家、法医、伙计那一类。他们：
- **不投票、不被投票**、没有个人目标、不进“谁赢了”的名单；
- 不参与搜证、圆桌、最终陈述、私聊结盟，但**自我介绍会露面**，玩家在**质询阶段可以问到他们**；
- 玩家不能扮演他们；
- 仍然需要时间线（他们当晚也在某个地方——这正是他们能目击别人的原因）。
- `private_secret` 对证人的含义是“问对了才肯说的关键信息”，`motive` 可以留空。

### 凶手的 `cover_story`

预生成的假口供。**不让 AI 现编谎话**是整个设计里一致性的关键。

```jsonc
"cover_story": {
  "claim": "一句话总口供",
  "fake_timeline": [ { "slot": "20:00", "claimed_location": "茶室", "claimed_action": "…" } ],
  "weak_points": [ { "clue_id": "c_abacus", "risk": "…", "fallback": "被戳穿时怎么圆" } ],
  "redirect_targets": ["t2"],          // 想把嫌疑引向谁
  "redirect_hook": "引导用的话头"
}
```
`fake_timeline` 尽量覆盖所有时段——没覆盖的时段被追问时 AI 只能现编，容易崩。

## 4. 时间线 `timeline[]`

**必须是完整矩阵**：每个角色 × 每个时段都要有一条，一格不能空。

```jsonc
{ "slot": "20:00", "char": "t1", "location": "库房", "action": "…",
  "witnessed_by": ["t2"],          // 谁看见了他（同时段同地点的人）
  "observed": ["他注意到的事"],     // 他自己看到的细节
  "is_crime_action": true }        // 凶手在案发时段的那一格
```

- **目击必须对称**：A 被 B 目击，则 B 同时段必须和 A 在同一地点。
- **凶手必须在案发时段出现在案发地点**。
- 手写这个矩阵最容易出错。用 `scripts/_scriptkit.py` 的 `build()`：你只写“谁在哪”的表，
  `witnessed_by` 由它按同地点**自动推导、天然对称**。

## 5. 线索 `clues[]`

```jsonc
{ "id": "c_ash", "location": "后厨", "text": "玩家看到的原文",
  "reveals": "这条线索说明什么（只有校验器看）",
  "points_to": ["t1"],          // 指向谁（只有校验器看）
  "is_red_herring": false,      // 红鲱鱼：看着有用，其实是误导
  "difficulty": 1 }             // 搜索顺序键，见下
```

**搜证怎么分线索**：同一地点第 N 次被搜，固定返回第 N 条（按 `difficulty` 升序，同分按 id 排）——
确定性，不随机。所以 `difficulty` 本质是“这个地点第几次才搜得到”。

**要写够**：全场一共搜 `嫌疑人数 × search_budget 之和` 次。线索少于搜证次数，就会出现
“已经被翻遍了，一无所获”——玩家白白浪费名额。`check_script` 会算给你看。

**至少一条红鲱鱼**。关键线索（`minimum_clues_required`）里不能混红鲱鱼。

### 合成线索——这个机制是三幕本的灵魂

单看毫无意义，**两条凑在一起**才产生第三个结论。

```jsonc
{ "id": "s_burnt", "location": "", "synth": true,
  "from_clues": ["c_ash", "c_seal"],
  "text": "拼出来的结论",
  "combine_note": "拼成当场的旁白：你把 A 和 B 摆到一块儿……",
  "reveals": "…", "points_to": ["t1"] }
```

- **按人算，不是全局**：谁**同时握有**所有 `from_clues`，谁就自动得到它。
  A 手里有一半、B 手里有另一半，谁也拼不出来——得在私聊里交换。这是白送的设计。
- 合成线索 `location` 留空、`synth: true`，**不会出现在任何搜证池里**。
- 合成线索可以当另一条的原料（链式）；成环会被校验拒收。
- 拼成时只有拼出它的那个人看得到“💡”提示，别人不知道你刚发现了什么。
- 复盘时会列出“没人拼出来的推论”——差一步就想通的东西，是最值得看的一段。

### 随身线索——不是搜出来的，是“本来就在他身上”

手机里一直在录的音、医生藏在药箱夹层里的旧笔记、死者写给某人的那页信。
这类东西没有“地点”，搜不到，只能由某个人的某一幕剧本**发给他**。

```jsonc
// clues[] 里
{ "id": "g_audio", "location": "", "granted": true,
  "text": "【岑晚的手机录音】……", "reveals": "…", "points_to": ["t1"] }
// characters[].acts[] 里
{ "act": 2, "text": "……", "grant_clues": ["g_audio"] }
```

- 拿到之后，他可以公开、私下给人看，也可以烂在肚子里——要不要说，是这个角色的选择。
- 随身线索可以和别人搜到的线索一起当合成线索的原料（比如“录音里的木珠声 + 冷库地上的珠子”）。
- 也可以用幕间的 `reveal_clue` 把它公开给所有人（比如县局打来的电话）。
- 校验：`granted` 线索 `location` 留空；`grant_clues` 里引用的必须存在且标了 `granted`；不能同时是 `synth`。

## 6. 追加剧本 `acts[]`（三幕）

第二幕不是“再搜一轮”，而是**每个人收到一页只有自己知道的新信息，而且它通常会推翻他前面说过的话**。
这是线下本能撑好几个小时的真正原因：不是内容多，是同一批信息被反复推翻重估。

```jsonc
"acts": [
  { "act": 2, "title": "你想起来了",
    "text": "追加正文，原样展示给玩家、喂给 AI",
    "observations": ["并入“你注意到的事”"],
    "secret_add": "这一幕才揭晓的、关于自己的秘密",
    "goals": [ {"id":"t1a2g1","type":"conceal","text":"…"} ],   // 这一幕新增的目标
    "retract_goals": ["t1g2"],                                    // 不再适用的旧目标
    "restore_slots": ["20:00"] }                                  // 想起来的断片时段
]
```

- `act` 从 2 起，每人每幕最多一页。
- **追加目标就要退休旧目标**（`retract_goals`），否则目标越堆越多，“全部达成”的概率塌到接近零，
  四档判定就剩两档了。
- 视角切分按当前幕给：第一幕的视角里**不存在**第二、三幕的内容——不是“藏起来”，是切不出来。

### 幕间 `interludes[]`

```jsonc
{ "at": "act2",                          // 第二幕开场；act3 = 第三幕开场
  "title": "…", "text": "…",
  "effect": "reveal_clue",              // none / reveal_clue / unlock_location
  "clue_id": "c_x"                      // reveal_clue：这条线索公开给所有人
}
{ "at": "act2", "effect": "unlock_location", "location": "阁楼", "text": "…" }
```
`unlock_location` 解锁的新地点**不用写进 `setting.map`**，直接给它放线索即可。
同一幕可以写多条。幕间的作用只有一个：**让玩家刚建立起来的结论站不住**。

## 7. 断片 `amnesia_slots`

这个角色对这些时段**没有记忆**：自己的行踪表里这几格是空的，对应的“注意到的事”也拿掉了。
对 AI 同样生效——它会老实说“我不记得”，而不是照着真相演。

玩家得靠**别人的目击、现场的物证**倒推自己当时干了什么。别人眼里的他，仍然在别人的视角里。
- 想起来的时段在某一幕的 `restore_slots` 里写。
- **凶手不能有断片**（他要演假口供）。

## 8. 答卷（分层真相）`solution.questions[]`

原来整局只有一个问题：谁是凶手。现在可以多问几个，各自判分：

```jsonc
"questions": [
  { "id": "q1", "prompt": "谁先动的手？", "kind": "character", "answer": "t1", "points": 2,
    "explain": "复盘时展示的解析" },
  { "id": "q2", "prompt": "他在哪里遇害？", "kind": "location", "answer": "库房" },
  { "id": "q3", "prompt": "起因是什么？", "kind": "choice", "answer": "b",
    "options": [ {"id":"a","text":"…"}, {"id":"b","text":"…"} ] }
],
"question_pass": 0.6
```

- 三种题型：选人 / 选地点 / 自定义选项。**全是选择题，纯代码判分，不调 AI**——胜负必须是确定的。
- 答对 `question_pass` 以上才算“把案子还原了”。票对了凶手但没过线，只是**惨胜**。
- 玩家本人是凶手时不考（他知道真相）。
- 不写 `questions` = 老样子，只有投票这一问。
- 题目下发给前端时**不带答案和解析**。

## 9. 自检做了什么

`python scripts/check_script.py 你的文件.json`，由硬到软：

1. JSON 能解析（出错告诉你行列）
2. 字段齐全、类型正确
3. 一致性：时间线矩阵、目击对称、凶手在现场、线索地点、合成链不成环、答卷答案合法……
4. **逐幕、逐角色的信息泄漏检查**——第 1 幕的视角里不能有别人的秘密，也不能有自己第 3 幕才揭晓的东西
5. 离线试玩（不调模型）：分别扮演第一个嫌疑人、凶手、断片的角色，从开场打到复盘

过了 1–5 才能上架。另外还有一批“建议”（线索太短、搜证次数和线索数对不上、目标像截断的病句、
三幕本缺追加剧本……），不挡上架，但值得看一眼。

> `load_script` 校验不过的本子会被选本页**静默跳过**。想知道为什么没出现：
> 访问 `GET /api/scripts/errors`，或者直接跑 `check_script`。

## 10. 几条写作上的经验

这些是反复踩出来的，不是理论：

- **线索写“读完能和别的线索对上”的细节**，不要写“读完即用完”的事实。
  “后门的插销是拔开的”读完就没了；“插销是拔开的，且门轴上的油是新擦的”才有得拼。
- **目标要写满句子**。AI 和玩家读到半截话都会困惑。
- **每个人都要有一个“不想让人知道的事”**，而且它最好**不是**杀人。
  这样每个人说话都会闪烁，凶手才藏得住。
- **追加剧本要有“翻转”**：让玩家觉得“我之前说的话要糟了”或者“我之前怀疑错了”。
  只是补充细节的追加剧本，等于没写。
- **别把答案写进 `public_role` 和背景里**。校验器能抓“别人的秘密原文”，抓不住你换了个说法的暗示。
- 先写**真相**（谁、怎么、为什么、时间线），再写线索——不要先写线索再倒推真相，会前后矛盾。
