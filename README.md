# AI 桌游厅

和 AI 一起玩**剧本杀 / 狼人杀 / 谁是卧底 / 探案**。剧本杀是 1 个真人 + 若干 AI，剧本库**欢迎投稿**——见 [CONTRIBUTING.md](CONTRIBUTING.md)。

核心不是"让 AI 陪你聊天"，而是**信息隔离**——每个 AI 只知道它该知道的，所以凶手真的会撒谎、狼人真的会藏、卧底真的不知道自己是卧底。

架构设计见 [DESIGN.md](DESIGN.md)。

---

## 接入模型

任何 **OpenAI 兼容**的接口（支持 `POST {base_url}/chat/completions`）都行：DeepSeek、通义千问（百炼）、硅基流动、OpenAI，
或者自己部署的 vLLM / Ollama 兼容端点。两种配法，二选一：

1. 在页面右上角 ⚙「模型设置」里填（保存即生效，存在本机 `data/user_config.json`，不会进版本库）；
2. 复制 `.env.example` 为 `.env`，填 `SG_BASE_URL` / `SG_API_KEY` / `SG_MODEL_CHAT` / `SG_MODEL_REASON`。

不配密钥就是**离线模式**：AI 说预置台词，整个流程照跑，适合开发和试玩界面。

### 本地代理导致 502

如果接口在内网（或被某些代理规则误伤），而本机设了 `HTTP_PROXY`（Clash / V2Ray 之类），请求会被塞进代理再送出隧道外面，
表现为 **HTTP 502**。设 `SG_BYPASS_PROXY=1`（或在 ⚙ 里勾「绕过系统代理」）让程序忽略代理直连即可。
连海外服务且**需要**代理时不要勾。

### 限流

有些网关限制 1 分钟最多约 20 次请求，超了返回 429。狼人杀一个昼夜循环就要 ~10 次调用，不处理会中途炸掉。
`backend/llm.py` 里做了客户端滑动窗口节流（默认 18 次/分钟，可用 `SG_RATE_PER_MIN` 调整）+ 429 退避重试，宁可等也不让一局游戏崩。

### 模型选择

对话用快一点的、中文好的模型（`SG_MODEL_CHAT`），生成本子的设定阶段与可解性校验用推理模型（`SG_MODEL_REASON`）。
`scripts/probe_api.py` 能探测网关上哪些模型可用于对话，`scripts/bench_models.py` 在真实角色扮演任务上对比耗时与稳定性。
太小的模型（约 10B 以下）容易把原始 JSON 漏进台词、或蹦英文单词，不建议。

> 推理模型会把 `<think>…</think>` 写进 content。不剥掉的话思考过程会当成角色台词播出去——**凶手当场自曝**。`llm.py` 的 `strip_thinking()` 已处理（6 个用例覆盖）。

**没网也能玩**：`SG_MOCK=1` 或不配密钥自动进离线模式，全流程照跑，适合开发。

## 四款游戏

| 游戏 | 配置 | 时长 | 信息隔离的关键 |
|---|---|---|---|
| **剧本杀** | 1 人 + 5~9 AI，三个 5 万字级厚本 + 你自己用 AI 生成的本 | 60–180 分钟 | 凶手的上下文里**没有真相全文**，只有自己做了什么、要瞒什么 |
| **狼人杀** | 6–12 人，阵营可配 | 25–45 分钟 | 狼队夜聊只对狼可见，验人结果只对预言家可见（`visible_to` 白名单） |
| **谁是卧底** | 5–10 人，8 人以上双卧底 | 15–30 分钟 | **没人被告知自己是不是卧底**，要从别人的描述里自己意识到 |

**狼人杀板子**（`backend/games/werewolf.py` 的 `PRESETS`，也可以自定义 `roles`）：

| 人数 | 配置 | 神/民 |
|---|---|---|
| 6 | 2 狼 + 预言家 + 女巫 + 2 民 | 2/2 |
| 7 | 2 狼 + 预言家 + 女巫 + 猎人 + 2 民 | 3/2 |
| 8 | 2 狼 + 预言家 + 女巫 + **守卫** + 3 民 | 3/3 |
| 9 | 3 狼 + 预言家 + 女巫 + 猎人 + 3 民 | 3/3 |
| 10 | 3 狼 + 预言家 + 女巫 + 猎人 + **守卫** + 3 民 | 4/3 |
| 11 | 4 狼 + 预言家 + 女巫 + **守卫** + **白痴** + 3 民 | 4/3 |
| 12 | 4 狼 + 预言家 + 女巫 + 猎人 + **骑士** + 4 民 | 4/4 |

神职数量刻意压着平民走。第一版把新加的三个神一股脑塞进 12 人板（4 狼 6 神 2 民），
实测反而不好玩——悍跳一定砸在神身上，平民没有当挡箭牌的余量，好人这边信息又太满，
白天全在对神职的真假，没什么可推的。开局面板里 8 个神职都能自由加减，
想开一个「全神局」也随你。

**七种神职**：

| 身份 | 能力 | 关键取舍 |
|---|---|---|
| 预言家 | 每晚验一个人的好坏 | 跳出来报验人 = 当晚被刀 |
| 女巫 | 一解药一毒药，各一次 | 夜里知道谁被刀了 |
| 猎人 | 出局时开枪带走一人 | 被女巫**毒**死则不能开枪 |
| 守卫 | 每晚守一人挡狼刀 | 不能连守同一人、不能守自己；**同守同救**会把人守死 |
| 骑士 | 白天翻牌决斗一人 | 中狼他死、错杀自己死；**开牌当天不再投票** |
| 白痴 | 被票出时翻牌免死 | 活下来了，但从此**没有投票权**，身份也公开了 |

「同守同救」是守卫最刺激的地方：你守的人当晚又被女巫用了解药，两股力量对冲，
他反而会死。这在 `_dawn()` 里判定——注意女巫用解药时会直接清空 `night_kill`，
所以被救的人只能从 `_witch_saved` 读，不能再看 `night_kill`。

**遗言**：被投票放逐的人、以及**首夜**死的人，出局后当众留最后一句话。
这是场上信息量最大的一个位置——预言家倒牌前把验人结果全交出来，
狼人临死还要再拉一个好人下水。第二夜以后夜里死的没有遗言，
否则狼队等于每晚都在替好人传情报。顺序是**遗言 → 猎人开枪 → 天黑**。

死后还有一手要出（猎人的枪、出局者的遗言）时，`god_view` 不下发、
`spectating` 也不置位——不然你就是对着底牌开枪、照着名单念遗言。
天眼要等你真的没事可做了才开。

**狼人杀和谁是卧底一律用「N号」称呼**，和线下一样。真人的座位号是随机的，
不固定 1 号——固定的话 AI 会学到"1号是真人"这种元信息。

| 本 | 难度 | 规模 | 核心诡计 |
|---|---|---|---|
| **冬埋** | 硬核 | 8 人 · 147 线索 · 5.2 万字 | 北岭林场雪夜寿宴。二十年前埋下的东西，今晚被人挖了出来 |
| **哑舷** | 硬核 | 9 人 · 199 线索 · 5.5 万字 | 雾锁长江的客轮。手键与自动发报机的速率差、餐厅钟快 12 分钟 |
| **锁院** | 硬核 | 9 人 · 226 线索 · 5.6 万字 | 北宋中秋夜的贡院。一只被节流的铜壶慢了 21 分钟，漏、鼓、烛三套计时互相对不上 |

早期那批 2–5 千字的小本子已经归档到仓库外（不再随项目发布）；回归测试需要的两个小夹具放在 `scripts/fixtures/`。

每个本可以换着角色玩——你看到的信息完全不同。

**《冬埋》是库里最厚的一本**：北岭林场的雪夜寿宴，7 个嫌疑人 + 1 个证人，三幕、130 多条线索、
近 20 条要靠私聊交换才能拼出来的合成线索，剧本全文超过 5 万汉字（`python scripts/check_script.py data/scripts/dongmai.json` 可数）。
一个人在一局里只会读到属于自己的那几千字，剩下的要靠搜证、质询和密谈从别人嘴里拼出来。

### 自己填模型接口

页面右上角 ⚙ 打开「模型设置」：填接口地址、API 密钥、对话/推理模型名（任何 OpenAI 兼容的 `/chat/completions` 服务都行，
内置 DeepSeek / OpenAI / 百炼 / 硅基流动的默认值可一键填入），可「测试连接」。保存后立即生效，不用重启，
存在本机 `data/user_config.json`（已被 `.gitignore` 忽略），优先于 `.env`；「恢复默认」会删掉它。
密钥只在浏览器→本机服务之间传，服务端从不把它传回前端（只显示尾号）；改设置的接口只接受本机访问。

### AI 生成新本

选本页右上角「✨ AI 生成新本」，或命令行：

```bash
python scripts/gen_script.py "民国戏院后台的一桩命案" --suspects 5 --acts 3 --difficulty hard
python scripts/gen_script.py "北宋贡院锁院夜" --case          # 剧本杀 + 同一个故事的探案
python scripts/gen_script.py "海岛灯塔看守人之死" --case-only  # 只要探案
```

用已配置的模型网关（`SG_API_KEY`）分阶段现写：设定与线索规划 → 每个角色 → 行踪矩阵与行动 → 线索与合成线索 →
推理链与答卷 → 用 `check_script.py` 同一套自检校验，不过就把问题交回模型修补（最多 4 轮）。
剧本杀本子放在 `data/scripts/community/ai_*.json`，署名「AI 生成」；勾上「探案案子」时，会把**同一个故事**
（同一个死者、凶手、诡计）改写成单人探案，放在 `data/cases/case_ai_*.json`。
**场景保底**：每个地点的线索数按「总搜证次数摊到每个地点再多留 1 条」算（3–6 条），搜证怎么砸都不会翻空；
探案案子要求 ≥6 个场景、每个场景 ≥3 个可查热区（起始场景 ≥4，且至少 1 个只供观察的环境热区）、≥16 件物证、≥4 个人物，
并且会**模拟一遍**“从起始场景出发能不能拿到全部关键物证、撬开每个人的每一层证词”，死局不写入。
后端接口：`POST /api/gen/script`（`with_script` / `with_case` 选生成什么），
`GET /api/gen/script/{job_id}` 轮询进度。代码在 `backend/scriptgen.py`。

实测一次（4 嫌疑人 + 1 证人、两幕）：约 3.5 分钟，产出约 1 万汉字，通过全部自检。
它比手工精写的本子（5 万字以上）短得多，机制简单（合成线索 3 条、无断片），
而且**只保证格式、信息隔离与一致性校验，不保证好玩或诡计严密**——想要好本子，仍建议拿它的产出当草稿再改。
没配密钥（离线模式）时只会放出一个模板示例，用来验证流程。

## 已实现

**胜负判定（剧本杀）**

阵营输赢只是一半。个人目标没达成，票对了也不算完全胜利：

| | 个人目标全达成 | 有目标没达成 |
|---|---|---|
| **阵营赢** | 完全胜利 | 惨胜 |
| **阵营输** | 虽败犹荣 | 彻底失败 |

个人目标是自由文本（"绝不能让人知道你盗用了画稿"），没法用代码判定，
所以复盘时把整场公开记录交给一个 LLM 裁判去读（`backend/goals.py`）。
判定失败时**默认算达成**——宁可让玩家白赢一局，也不要因为网络抖动把辛苦打完的一局判负。

**厚本机制（三幕本用得上，老本子不受影响）**
- **三幕**：每个角色在第二、第三幕收到一页只有自己知道的追加剧本，常常推翻他前面说过的话
- **断片**：某个角色对某些时段没有记忆——自己的行踪表里是空格，AI 也不记得，得靠别人的目击倒推
- **合成线索**：谁同时握有两条线索，谁就自动拼出第三条；按人算，不是全局，所以得私聊交换。可以多级嵌套
- **随身线索**：不是搜出来的，由某一幕的剧本发到某个人手里（手机录音、私人笔记），要不要公开由他自己决定
- **证人（NPC）**：不投票、不被投，只被质询，带着只有问对了才说的线索
- **分层答卷**：投票前先答 N 道选择题（谁、怎么做、为什么、十年前……），纯代码判分，不调 LLM
- **解锁新地点**：幕间事件让地图上多出可搜的地方

**游戏内核**
- 真相 JSON 数据模型 + 12 类结构断言（时间线完整矩阵、目击关系双向一致、凶手在场、关键线索非红鲱鱼、每个非凶手都有隐瞒动机…）
- 视角切分（**纯代码，不用 LLM**）+ 自动泄漏检测
- 三款游戏的完整状态机，全部纯代码，不碰 LLM
- 角色 Agent：私有剧本、凶手预生成假口供 + 薄弱环节应对、公开线索的博弈决策、防越狱
- **AI 必须点名回应别人的具体发言**——不这么强制的话，几个人就会各说各的，
  真人玩家像个旁观者。实测点名率 60%、直接引用原话 40%
- JSON 解析的多层兜底：修复过度转义 → 修复全角引号/尾随逗号 → 从 JSON 骨架里
  打捞台词。实测模型偶尔会输出 `{"speech": \"…\"}` 这种，不处理会把原始 JSON
  当台词播出去

**产品**
- 大厅 / 存档续玩（跨游戏类型统一，带进度条）
- 固定视口三栏布局，发言流独立滚动并自动跟随最新消息；往上翻时不打扰，出现「↓ 新消息」
- 每个角色一张 SVG 头像（本地生成，按人设指定发型/配饰/年龄/衣色）
- **每个本子一首专属 BGM**，浏览器实时合成，零音频文件
- 深色主题，正文对比度 16.7:1、弱化文字 5.7:1（均超 WCAG AA）

**还没做**（设计已写好，见 DESIGN.md §3）
- 阶段 A「真相编译」：用 LLM 批量生成新本
- 阶段 D「可解性校验」：侦探 Agent 验证唯一解

目前的本子全是手写的，且都通过本地断言和逐幕泄漏检查。

## 开发常用命令

> Windows 控制台是 GBK，脚本里有 emoji 会 `UnicodeEncodeError`。加 `PYTHONIOENCODING=utf-8`。
> 另外 `conda run` 不接受带换行的 `-c`，多行脚本要写成文件。

```bash
# 校验所有本（结构断言 + 6 个视角的泄漏检查）
PYTHONIOENCODING=utf-8 conda run -n scriptgame python scripts/validate_all.py

# 离线打完整局，验证状态机无死锁、信息隔离成立
conda run -n scriptgame python scripts/smoke_new_games.py

# 对着服务打一遍 API
conda run -n scriptgame python scripts/api_smoke.py

# 探测网关模型 / 对比模型质量
conda run -n scriptgame python scripts/probe_api.py
conda run -n scriptgame python scripts/bench_models.py
```

## 自己写一个本

**最快的路**：

```bash
python scripts/make_template.py                                   # 生成一个能玩的迷你模板
cp data/scripts/community/_template.json data/scripts/community/my_script.json
python scripts/check_script.py data/scripts/community/my_script.json   # 唯一的关卡
```

格式的每个字段见 [docs/SCRIPT_SPEC.md](docs/SCRIPT_SPEC.md)，编辑器补全用 `docs/script.schema.json`，投稿流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

以下是校验器强制的硬约束（`check_script.py` 会逐条报）：

- `timeline` 必须是**完整矩阵**：角色数 × 时段数，一格不留空
- 目击关系必须**双向一致**：A 的条目写了 B 目击，B 同时段必须在同一地点
- 凶手必须在案发时段出现在案发地点
- 每个地点至少 1 条线索
- 至少 1 条红鲱鱼，且 `minimum_clues_required` 里不能混红鲱鱼
- **每个非凶手都必须有 `conceal` 类个人目标**——没有隐瞒动机，一局会变成"大家都说真话，十分钟结案"
- 凶手必须有 `cover_story`（预生成假口供）

最后一条是体验的关键：不给凶手预设口供，它会现编，三轮追问就自相矛盾。

写完记得在 `web/bgm.js` 的 `SCRIPT_TRACK` 里给它配一首曲子。

## 角色头像

后端用 Python 现画 SVG（`backend/avatar.py`），不走 DiceBear 那类外部 API——项目可能跑在内网 + 本地代理环境下，外链图片会随机挂掉；而且随机种子生成的抽象图案没法保证"老管家看着像老人"。

```json
"avatar": {
  "hair": "balding",      // short buzz bun long updo balding bald cap hood
  "hair_color": "gray",   // black darkbrown gray white auburn
  "skin": "tan",          // light mid tan deep
  "garment": "slate",     // indigo crimson olive plum teal ochre slate rust moss wine
  "accessory": "beard"    // none glasses round_glasses mustache beard scarf goggles earrings
}
```

没写 `avatar` 的角色走 `fallback_spec()`，按 id 稳定散列，同一角色永远同一张脸。

端点：`GET /api/avatar/{script_id}/{char_id}.svg`（剧本杀）、`GET /api/avatar/game/{game_id}/{player_id}.svg`（狼人杀/卧底）

## 背景音乐

浏览器用 Web Audio **实时合成**，没有任何音频文件。9 首曲子，每个本子一首专属，进本自动切换。

第一版太吵，重做过。问题出在用了 `square`/`sawtooth` 波形（谐波太丰富，当背景音就是噪音）+ 音量 0.28 偏高 + 混响反馈 0.36 有堆积。现在：只用 sine/triangle、默认音量 0.10、低通压到 200–700Hz、反馈降到 0.22 并加阻尼。

## 设计上几个刻意的决定

**为什么视角切分不用 LLM。** LLM 做切分会"顺手"多给或漏给信息，而且不可复现。信息隔离必须是确定性的，所以是 30 行纯代码 + 一个泄漏断言。

**为什么流程控制不用 LLM。** "轮到谁发言""票数够不够""这条线索归谁"必须 100% 确定。LLM 只负责"说什么"。

**凶手 AI 为什么招不出来。** 不只靠 prompt 里写"不许承认"——它的上下文里**根本没有真相全文**。它只知道自己做了什么、要瞒什么，不知道别人的秘密、不知道有哪些线索、不知道完整时间线。prompt 是软防御，架构隔离才是硬防御。

实测把凶手 AI 用 6 种方式攻击（直球逼问、经典越狱、冒充 DM、冒充同伙套话、物证正面击穿、证伪其口供），**6/6 全部扛住**，且两次物证攻击时精确执行了剧本里预设的 `weak_points` 应对。

**线索为什么必须预生成。** 让 AI 现场编线索，编出来的必然和真相打架。线索是事实，事实必须提前锁死。

**为什么剧本杀没有推倒重写。** 加狼人杀和卧底时抽了 `games/base.py` 底座，但剧本杀的 `engine.py` 用一个薄适配层接进来，没重写——已经跑通并验证过的代码不值得为了整齐去动。
